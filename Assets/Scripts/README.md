# スクリプト構成

| フォルダ | 役割 | Unityへの依存 |
|---|---|---|
| `CardSystem/` | ルール（山札・吉凶・運気・倍率・破綻・精算） | なし（asmdefで禁止） |
| `Game/` | 3D表示・HUD・入力・進行のつなぎ込み | あり |
| `Editor/` | メインシーンの自動生成 | エディタのみ |
| `Development/` | 山札だけを確認する旧テスト表示 | あり |

## ルールの流れ
1. `Customer.CreateRandom` で客を作る（凶数＝ランダムな1つの数字2枚＋ジョーカー、吉数＝別の1つの数字2枚）
2. `ReadingSession` に客と `Deck` を渡す
3. `TryDraw` で1枚引く／`TryStop` で鑑定を終える
4. 結果は `ReadingResult`（売上・予感的中・霊力）。スコア＝売上

数値の調整は `ReadingRules`（鑑定・道具のコスト）と `RunRules`（客数・ノルマ・初期霊力）だけを変えます。

## 夜と占い道具
- `PlayRecord`：夜・ノルマ・スコア・霊力。1夜＝客3人×3夜。ノルマ未達でも最後の夜まで続き（`RunRules.QuotaFailEndsGame` で切り替え）、最後に夜ごとのスコアと合計を表示
- 占い道具は `ReadingSession.TryUseTool` で使う（霊力は `PlayRecord` から払う）
  - 水晶（1）：次が凶か分かる／タロット（2）：次の3枚の数字（順不同）
  - お香（2）：凶札を1枚除く（1人1回）／手相（1）：一番上を一番下へ

## ReadingSession のイベント
| イベント | タイミング | 引数 |
|---|---|---|
| `CardDrawn` | カードを引いた | `DrawResult`（カード・吉凶・運気・倍率・凶の数） |
| `LuckyDrawn` | 吉数を引いた | 新しい倍率 |
| `BadOmenDrawn` | 凶を引いた | 凶の印の数 |
| `Broken` | 破綻した | `ReadingResult` |
| `Settled` | 鑑定を終えて確定した | `ReadingResult` |
| `Finished` | 破綻・確定のどちらでも | `ReadingResult` |
| `ToolUsed` | 占い道具を使った | `ToolResult` |

イベントは引いた瞬間に発生します。演出の後に表示を変えたい場合は、`ReadingGameController` のように演出が終わってから状態を読みます。

## メインシーン
メニューの **Hikigiwa → メインシーンを作成** で `Assets/Scenes/Main.unity` を作り直します。
カメラ・照明・仮のテーブルもここで作るので、部屋を作り込む段階になったらシーンを直接編集し、このメニューは使わないでください。

### ソロモードの部屋（Game.unity）
`Game.unity` を開いてメニューの **Hikigiwa → 開いているシーンに部屋を配置** を実行し、シーンを保存します（`Editor/SoloRoomPlacer.cs`）。
- 仮のテーブルを `UranaiRoom.fbx` に置き換えます。シーンのほかのオブジェクト（カメラ・HUD・進行）は変えません
- テーブルクロスの上面の中心と大きさを仮のテーブルに合わせるので、カードの配置はそのまま使えます（部屋は約1.9倍に拡大されます）
- テーブル上の水晶玉はカメラから見て奥に向けます。マテリアルは `Assets/Art/room/Materials` のものを使います

## UI（HUD）をシーンで編集する
ソロ（`Game.unity`）・CPU対戦（`CPUBattle.unity`）のUIは、メニューの **Hikigiwa → UIをシーンに配置** でHierarchyに書き出せます（`Editor/HudScenePlacer.cs`）。
- 書き出したUIは、位置・大きさ・色・フォント・固定の文言をエディタで自由に変えられ、プレイ時もそのまま使われます
- 数字やメッセージなど、プレイ中に変わる文字は実行時に上書きされます（エディタで入っている文字は配置確認用の仮の文字です）
- 部品は `ReadingHud` / `BattleHud` の「UIの部品」に割り当てられています。**部品を消すと動かなくなる**ので、移動・変形・非表示にとどめてください
- 結果パネル・占い道具パネルなどは、編集のために表示したまま保存しても、プレイ開始時に自動で隠れます
- UIが置かれていないシーンでは、これまでどおりプレイ開始時にコードで作ります

## CPU対戦

`Assets/Scenes/CPUBattle.unity` を開き、Unityの再生ボタンを押すと対戦が始まります。

- 山札クリック／Space／「1枚引く」でドロー、Enter／「辞める」で停止。
- T／「占い道具」で道具を開き、Esc／Tで閉じます。自分の手番では道具を使っても手番は終わらず、引くか辞めるまで続きます。
- ラウンド結果でEnter／「次のラウンド」。3ラウンド後はEnter／「もう一度対戦」で再戦。
- 各ラウンドの先手はランダム。19枚の山札、吉数1種類・凶数2種類は共通。凶札は数字札4枚＋ジョーカーの計5枚。運気・倍率・凶の印は個別です。
- 先に止めた側は予感なしで即時精算。相手が停止・破綻した後に止めた側だけ予感判定を行います。
- 山札切れ（お香で最後の札を除いた場合も含む）は、続行中の側を予感なしで通常精算します。
- 正常精算で霊力+1、破綻は0点で回復なし。各自の霊力は初期3でラウンド間に持ち越します。
- CPUは道具を使いません。初期設定では、凶0個なら必ず引き、凶を引いた後も残り山札の凶札率が50%未満なら引きます。手番開始時の凶札率が50%以上なら50%で止めます。凶札率には2種類の凶数とジョーカーを含みます。
- 占い結果はプレイヤー用HUDに表示し、共有山札が変わるときに消します。CPUは占い情報を判断に使いません。
- 3ラウンドの累計得点で勝敗を決め、同点は引き分け。ノルマ判定はありません。

| スクリプト | 役割 |
|---|---|
| `CardSystem/BattleMatch.cs` | 共有山札、手番、ラウンド進行、精算と累計 |
| `CardSystem/CpuBattleStrategy.cs` | CPUの停止判断 |
| `Battle/BattleGameController.cs` | 入力、CPUの待機、ルールと表示の接続 |
| `Battle/BattleCardDealer.cs` | Mainと共通のカード演出、二人分のカード配置 |
| `Battle/BattleHud.cs` | 対戦状況、道具、結果の表示 |
| `Editor/CPUBattleSceneBuilder.cs` | Mainのカード素材とroomモデルを使うシーン生成 |

机とカメラはメニューの **Hikigiwa → CPU対戦シーンを作成** で配置します（数値は `CPUBattleSceneBuilder.cs` の先頭の定数）。
- 部屋：二人分のカードが並ぶよう、部屋全体を `RoomScale`（1.5倍）に拡大する。カードの大きさは変えない
- カード：中央の数字が隠れない間隔（`CardColumnStep`・`CardRowStep`）で並べる
- カメラ：部屋の壁がある奥の角へまっすぐ向け、部屋の外が映らないようにする（`CameraDistance`・`CameraHeight`）

CPUの確率はCPUBattleシーンの **CPU対戦進行 → Battle Game Controller → CPUの停止判断** で調整します。
- **停止判定を始める凶札率（%）**：残り山札の凶札率がこの値以上なら停止を抽選します。初期値50。
- **停止する確率（%）**：抽選する手番で辞める確率です。初期値50。

両方とも0〜100で設定でき、再生中の変更は次のCPU判断から反映します。凶を引くまでは設定にかかわらず引き続けます。
例：凶札率30・停止確率70なら、凶取得後に山札の凶札率が30%以上の手番で70%の確率で辞めます。
再生中だけの変更はUnityの停止時に戻るため、保存する設定は再生を止めてから変更してください。

通常の調整はCPUBattleシーン上で行ってください。メニュー **Hikigiwa → CPU対戦シーンを作成** はシーンを作り直すため、手作業の変更を上書きします。

ルール検証は .NET 9 SDK で `dotnet run --project Tests/BattleRules/BattleRules.csproj` を実行します。
先行・後行の精算、破綻、山札切れ、道具、霊力持越し、既存の精算処理、1,000回の3ラウンド対戦を検証します。
